# Fixes to `lobbyapp/ui` — 2026-08-30

Two files changed: `app.css` and `app.js`. No markup changes, no string changes,
so `lobbyapp/ui_test.go` has nothing new to object to. Every fix below is
described where it happens, in the comment style already used in those files.

## On matching the design

The repo already implements the D68 redesign — the rail status stack, the
identity row at the top of the friends panel, filters above the column
headings, the room band with its stat strip, the (i) guide, observers on the
boards, Join Game / Create Game. Nothing structural needed changing. What
follows is defects found while reading it against the design components.

---

## Visual bugs

**1. The 1440px laptop adaptation never applied.** The
`@media (max-width: 1440px)` block was written *above* the base `.chip` rule.
Same specificity, so the later base rule won and the chips kept their full
padding at every width. Moved below the chips.

**2. Column headings sat two pixels off their own columns.** `.roomhead` was
padded `0 14px`, the `.room` rows it labels `11px 16px`. Same grid, different
padding, so all five headings were offset from their data. Both are 16px now.

**3. Doubled hairlines on the team boards.** Seat rules were drawn on the
bottom edge, so between seat five and the Watching header there were two
hairlines four pixels apart, and a third lay along the board's own bottom
border. Now drawn between adjacent rows (`.slot + .slot`): one line wherever
two rows meet, none anywhere else.

**4. The travelling light was a solid bar.** `.roomspanel .sweepline` and
`.roomband .sweepline` used a flat `--accent-lit` fill with two hard ends,
which reads as a rendering fault rather than as light. Both now use the same
fade-to-transparent gradient the front door already used.

**5. A long room name pushed the room band's actions onto a second line.**
Two causes: a nowrap flex item keeps its min-content width unless told
otherwise (`min-width: 0` on the `h2`), and under `flex-wrap` shrinking only
applies within a line, so the title also needed a small flex basis
(`flex: 1 1 180px`) instead of `auto`. Now it ellipses and the actions stay put.

**6. Stat values clipped without an ellipsis.** `text-overflow` does nothing on
a flex container, and `.stat .v` is one. A long host name or address was cut
mid-character with no sign it had been. The clipping moved to the text inside.

**7. `prefers-reduced-motion` did not do what its own comment claimed.** The
comment on the lobby decorations says both are "dropped whole" under reduced
motion; the media query listed neither, nor the Create room pulse, nor the
tunnel blink. All are listed now, plus the row and dock transitions. The pulse
keeps its accent ring — that ring was the only thing the loop carried.

**8. Duplicate declarations, where the second silently replaced the first.**
`.slot-name` (12.5px/600 then 13px/500), `.room-ping` (twice),
`@keyframes blink` (`.3` here, `.25` in the front-door section — the later one
had been winning for the rail dot all along), `#screen-room` (twice). Merged.
Removed `@keyframes pulse` and `.team-body`, both dead: `app.js` puts seats
straight into `.team`.

**9. Pure white overlay.** `.chattab .x:hover` used `rgba(255,255,255,.1)` in a
file whose own guidance is that no value comes from outside the ramps. Uses
`--panel3`.

## Right-to-left bugs

The file's header states every rule is direction-agnostic. Two were not, and
both are transforms — there is no logical equivalent, so each gets an explicit
RTL rule rather than a logical property.

**10. The sweeping light travelled the wrong way** under `dir="rtl"`: pinned to
`inset-inline-start` (the right edge in RTL) and then translated physically
right, so it left the panel almost immediately. Added `sweepline-rtl`.

**11. The magnifier's handle pointed into its own lens** under `dir="rtl"` —
`rotate(-45deg)` does not flip. Added the mirrored rotation.

**12. Room-list buttons were a fixed 62px.** That fits "Open" and "Join" and
nothing else; every label comes from the string catalogue and the Persian ones
are longer. Now `min-width: 62px` with real padding — the column is a fixed
width, so the button may grow inside it.

**13. `word-break: break-word` in the 48px rail column** breaks inside words
("servi/ce"). Now `overflow-wrap`.

## UX and accessibility

**14. No dialog could be dismissed with Escape.** Six of them — create room,
room settings, invite, profile, password, terms — and the only way out of any
was to find its own button with a mouse. Escape now presses the dialog's own
close control (so each still does its own cleanup: the terms remember how far
they were read, the profile form resets), and a click that both starts and ends
on the backdrop does the same. The chat's friend menu closes first if it is
open. The name gate is deliberately excluded: there is no application behind it
to go back to.

**15. Room rows, empty seats and friend rows were mouse-only.** All three are
whole-row targets, which is right — the row is what a player aims at — but each
was a `div` with an `onclick`: no tab stop, no role, no Enter or Space. A new
`pressable()` helper gives them exactly those three things. Buttons nested
inside them already stop their own clicks; they stop keys too, so Enter on a
Kick button does not also take the seat.

**16. Rows a keyboard can reach now show where the keyboard is.** An inset
accent ring, drawn inside the row — a ring outside a full-width row is clipped
on three sides by the list holding it.

**17. The chat dock took a third of a laptop screen.** A fixed 254px plus 26px
of margin, on the one screen (the room) that must fit 768px without scrolling.
Below 820px tall it gives back 60px — twice what the sticky footer needed.

## Left alone deliberately

- **`.ticks.full i.on` paints a full room's pips in `--bad`**, the same red used
  for a poor ping and for failures. A full room is information, not a fault. It
  is a product call, not a bug, so it is untouched — but `--warn` would read
  more honestly.
- **The filter chips behave as a single choice** (`setFilter` replaces rather
  than toggles) while the design components showed them as multi-select. Worth
  confirming which you want; changing it is a change to `app.js` behaviour, not
  a fix.
- **Room rows have no `aria-label`**, so a screen reader announces the row's
  full text content. Adding one means adding a string, and the build test
  guards the catalogue — left for you to decide.

## How to check it without the server

`scratch/css-check.html` renders the room list, the room band and both team
boards from the real `app.css` with hand-written markup that matches what
`app.js` produces. Open it directly in a browser. It carries three
preview-only overrides at the top (pinning the wide grid so a narrow window
still shows all five columns) — those are in the harness, not in `app.css`.
